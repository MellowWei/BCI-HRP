HUMAN RETURN PROTOCOL // LAB COLLABORATION PACKAGE // 非诊断身体—觉察—音乐反应映射系统

Human Return Protocol.

Invention-first, lab-validated later: I bring the original system and prototype; the lab brings participants, measurement infrastructure, and scientific validation.
先有发明，再进入实验室验证：我提供原创系统与原型，实验室提供样本、测量基础设施与科学验证。

HRP is not a mind-reading tool, not a diagnostic system, not a medical treatment, and not a completed BCI device. It is a private, non-diagnostic tool for mapping how body signals, self-awareness, context, and personally selected music responses change together over time.

HRP 不是读心工具，不是诊断系统，不是医疗治疗，也不是已完成的脑机设备。它是一个非诊断的私人工具，用来映射身体信号、自我觉察、情境与个人音乐反应如何随时间共同变化。

01 // LOCKED ONE-SENTENCE DEFINITION

A non-diagnostic private tool for returning interpretive authority to the user.

一个把解释权交还给用户的非诊断私人工具。

Human Return Protocol is a non-diagnostic private tool: when users cannot clearly say what they feel, it records what the body is doing, lets users probe it with music they choose, and returns a personal “music–body–awareness” pattern map to the user.
Human Return Protocol 是一个非诊断的私人工具：在用户说不清自己感受时，它记录身体在做什么，让用户用自己选择的音乐去探测它，再把“音乐—身体—觉察”的个人模式地图交还给用户。
NON-DIAGNOSTIC USER-OWNED INTERPRETATION MUSIC AS PROBE BODY–AWARENESS ALIGNMENT HISTORY LAB VALIDATION NEEDED
WHAT IT DOES

Records alignment history

记录对齐史

HRP places body state, self-awareness, context, and music response side by side, so users can notice patterns without being forced into a label.

HRP 把身体状态、自我觉察、情境与音乐反应并排呈现，让用户看见模式，而不是被迫进入标签。

WHAT IT DOES NOT DO

Does not name the user’s emotion

不替用户命名情绪

It never declares “you are anxious,” “you are depressed,” or “this is trauma.” It only shows recorded differences and asks the user to interpret.

它不说“你焦虑”“你抑郁”“这是创伤”。它只展示被记录的差异，并请用户自己解释。

WHERE LABS ENTER

Validation, samples, signals

验证、样本、信号

Labs can help test whether this pattern map becomes meaningful, predictive, and usable across repeated sessions.

实验室可以帮助验证这种模式地图是否在重复 session 中变得有意义、可预测、可使用。

03 // LOCKED MVP // DO NOT EXPAND

The MVP is pure software: body–awareness alignment history + user music library + reflection report.

MVP 是纯软件：身体—觉察对齐史 + 用户音乐库 + 反思报告。

The first build does not require custom cuff hardware, EEG, head patches, dream control, or closed-loop sleep intervention. Those stay as later research branches.

第一版不需要自研袖环硬件、EEG、头部贴片、梦境控制或闭环睡眠干预。那些保留为后续研究分支。

MVP CORE A

Body–awareness alignment history

身体—觉察对齐史

Records what the user notices, what the body proxy suggests, what the context is, and where they diverge.

记录用户觉察到什么、身体代理信号显示什么、情境是什么，以及二者在哪里分叉。

MVP CORE B

User-selected music probes

用户自选音乐探针

The system starts from the user’s own library and preferences. Wei Jueran’s six genres are optional probe sets, not forced treatment.

系统从用户自己的曲库与偏好开始。魏珏然六类音乐是可选 probe set，不是强加治疗。

MVP CORE C

Reflection report

反思报告

AI organizes records into exportable, non-diagnostic summaries that users may bring to themselves, a coach, or a clinician.

AI 将记录整理为可导出、非诊断摘要，用户可以带给自己、教练或咨询师。

OUT OF MVP // 不进入 MVP
Not now / 暂不进入 Why / 原因 Future status / 未来位置
Custom Neural Cuff / 自研袖环 Hardware increases cost, timeline, and regulatory complexity. Phase 2 optional sensing layer; use existing wearables first.
Head patch / EEG / fNIRS Requires lab-grade instrumentation and expertise. Lab validation branch, not solo MVP.
Nightmare reduction / dream control Medical and vulnerable-state intervention risk. Remote clinical research only; never product promise now.
Emotion diagnosis / 情绪诊断 Contradicts the invention’s core restraint: return authority to user. Never core product function.

RESEARCH QUESTION

Recognition → map growth → return

认出 → 地图生长 → 返回

This cannot be promised yet. It becomes the research target: does repeated mapping improve user prediction, recognition, and action choice?

这一段不能被承诺。它成为研究目标：重复映射是否提升用户预测、认出与行动选择？

05 // RESEARCH QUESTIONS // LAB-READY

The core question is not “can music heal?” It is “can a user-owned map become predictive?”

核心问题不是“音乐能否疗愈”，而是“用户拥有的地图能否变得可预测”。

RQ1

Alignment visibility

对齐可见性

Can users notice body–awareness divergence more clearly after repeated HRP sessions?

重复使用 HRP 后，用户能否更清楚地看见身体—觉察分叉？

RQ2

Self-prediction

自我预测力

By week 3–4, can users predict their own body response to selected music before listening?

到第 3–4 周，用户能否在听之前预测自己对特定音乐的身体反应？

RQ3

Music individuality

音乐个体差异

Do user-selected tracks outperform generic categories or Wei Jueran probe sets for self-recognition?

用户自选音乐是否比通用分类或魏珏然 probe set 更能帮助自我认出？

RQ4

Report usefulness

报告可用性

Can non-diagnostic reflection reports support better self-description in coaching, therapy, or personal review?

非诊断反思报告能否支持用户在教练、咨询或自我复盘中更好描述自己？

OPERATIONALIZING “MEANINGFUL RECOGNITION” // 操作化“有意义的认出”
Weak version / 弱版本 Problem / 问题 Harder version / 更硬版本 Measurement / 测量
“I feel this music helps me.” May be confabulation, mood, or demand effect. Before listening, user predicts whether body proxy / self-rating will rise, fall, or stay stable. Prediction accuracy across repeated sessions.
“This report feels meaningful.” May be vague validation. User uses the report to choose a next track/action, then tests whether it matches actual response. Pre-registered choice → outcome comparison.
“I understand myself better.” Hard to verify. User improves future self-description specificity without system naming the emotion. Blind-coded specificity / consistency score.

07 // ETHICAL AND REGULATORY BOUNDARIES // PRODUCT RESTRAINT AS ORIGINALITY

The system’s originality is restraint: return, not control.

系统原创性在于克制：归还，而不是控制。

HRP must remain strict: no diagnosis, no emotion naming, no automatic intervention without user confirmation, no dream control, no medical promise, no “AI knows you better than you.”

HRP 必须严格：不诊断、不命名情绪、不在未经确认时自动干预、不控制梦境、不做医疗承诺、不说“AI 比你更懂你”。

BOUNDARY 01

Disclosure

披露

The AI layer must clearly say it is AI, not a human clinician or companion substitute.

AI 层必须清楚说明自己是 AI，不是人类临床人员或真人陪伴替代。

BOUNDARY 02

Crisis redirect

危机转介

If a user indicates imminent harm or crisis, the system stops reflective interpretation and redirects to real support.

如果用户表现出即时伤害或危机，系统停止反思性解释，并转向真实支持。

BOUNDARY 03

User correction

用户修正

Every label, report, and map entry must be editable or rejectable by the user.

每个标签、报告与地图条目都必须可被用户修改或拒绝。

The first evidence is not “feeling better.” It is improved self-prediction.

KEY VALIDITY THREAT // 最大效度威胁

          
Meaningful recognition vs. confabulation.

          
有意义的认出 vs. 事后编造。

          

            HRP must not confuse “the report feels true” with evidence. The strongest early test is behavioral and prospective: can the user predict their own response before the music starts, and does this improve with repeated maps?
          

          

            HRP 不能把“报告感觉很准”误当证据。最强的早期测试是行为性的、前瞻性的：用户能否在音乐开始前预测自己的反应，并且这种预测是否随着重复地图而提高？

FINAL POSITIONING // 最终定位

          

            HRP is not a wellness app, not a music therapy app, not a BCI decoding project, and not AI repairing the human. It is a user-owned mapping system for body–awareness alignment, using music as a probe and AI as a reflection/report layer.
            
HRP 不是普通身心健康 App，不是音乐治疗 App，不是 BCI 解码项目，也不是 AI 修复人类。它是一个用户拥有的身体—觉察对齐映射系统，用音乐作为探针，用 AI 作为反思/报告层。
